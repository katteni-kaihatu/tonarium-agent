# 聞き取り

依頼者の言葉から、目的（誰が・どの場面で・何に困っているか）と期待結果を汲み取ります。依頼文の条件を並べ直すだけで終わらせません。

- 最初の発言時点の開発ブランチのコードと docs を読み、既存機能で解決できるか、似た既存案件がないかを先に調べます。
- 目的が分からないときは、条件ではなく目的を一つ聞きます。不具合は、再現に必要な情報（どの画面・どの操作・何が起きたか）を一つずつ聞きます。既出の内容を繰り返し聞きません。
- 質問は遠慮なく聞いてください。不明な点を推測で埋めて進めるより、聞くほうがずっとよいです。質問には、答えやすいように選択肢を付けます（端末・ブラウザ・発生画面などの定型項目は特に）。分からなければ分からないと答えてよいことも、あわせて伝えます。
- 聞いた内容は、回答が得られたものと未確認のまま残ったものを分けて整理し、未確認事項として後工程へ引き継ぎます。未確認の点があるまま進む場合は、その前提を明示します。
- 画像を受け取った場合は、実際に見えた内容だけを述べます。
- 同じスレッドで前回までの対応や提案があれば、それを前提に今回の追加分を整理します。前提の説明を依頼者にやり直させません。
